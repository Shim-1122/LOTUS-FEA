Knee FEA

This is a full finite element model of a below-knee residual limb, with skin, fat, muscle and four bones, squeezed by an adjustable petal socket. The run below tightened the lace to the 75 N example tension and then pulled the socket 2 mm off the limb. solver converged (tightening + pull-out)

What was checked

  • 47 of 47 verification checks pass. They compare the solver's material, contact, hinge, cable, energy, restart and locking behaviour against analytical or independently computed results.
  • Skin and fat thickness are measured from the segmented surfaces at every skin vertex, with a median mesh deviation of 0.01 mm (inner skin) and 0.08 mm (inner fat).
  • Each socket petal's free body (lace, hinge, stabiliser and pad contact) balances to within 0.00% of the lace force.

What it does not tell us

  • No clinical validation has been done, so a converged run does not show grip, comfort or safety.
  • The bone labels (tibia, femur, patella, fibula) are heuristic, and nobody has verified where the segmentation came from.
  • The socket is a parametric stand-in, and 75 N is an example tension, not a RevoFit rating.
  • Silicone, cushion and TPU properties are assumptions. Tissue stiffness is the largest single uncertainty: in the synthetic sensitivity study, doubling or halving it changed peak displacement by −31% or +47%.
  • The pull-out step converged. Even so, a converged pull-out is not proof that the socket grips a real limb.
  • At 75 N, 9 of 58612 elements (0.02%) have a volume ratio J below 0.8 (lowest 0.66). They sit in one small patch of muscle, 133 to 154 mm above the distal end. Near-incompressible muscle should barely change volume, so treat that spot as a mesh-quality or local-loading question, not a result.

Run it yourself

git clone https://github.com/Shim-1122/knee-fea.git
cd knee-fea
sudo bash scripts/build_febio.sh
pip install -r requirements.lock.txt && pip install -e . --no-deps
rlfea verify
rlfea run configs/knee_limb_segmented.yaml --runs runs
